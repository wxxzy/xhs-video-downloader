# 08 · 踩坑实录与经验沉淀

> 这一篇没有新功能，只有**代价换来的经验**。
> 每条按「现象 → 根因 → 对策」写，方便你在别的项目里遇到相似情况时直接套用。

---

## 一、数据层

### 1. `page.evaluate` 返回整个 `__INITIAL_STATE__` 得到 `None`

- **现象**：代码不报错，但返回值是 `None`，提取到 0 条笔记。
- **根因**：Vue 响应式对象有循环引用，跨进程序列化静默失败。
- **对策**：只传基本类型。在页面内逐字段拆成字符串，用 `、` 之外的自定义分隔符拼回；
  Python 侧再解析。项目用的是 `` ` ``（字段）、`~`（子字段）、`^`（多条）、`\x01`（多行）。
- **通用原则**：跨语言边界永远不要传复杂对象。

### 2. Vue `ref` 的真实值藏在 `._value`

- **现象**：`s.note.noteDetailMap` 看起来是对象，但 `Object.keys()` 为空或结构不对。
- **根因**：Vue 3 的 ref 包装。
- **对策**：取值前统一解包：
  ```js
  let dm = s.note.noteDetailMap;
  if (dm && dm._value) dm = dm._value;
  ```

### 3. 字段命名 snake_case 与 camelCase 混用

- **现象**：接口返回 `master_url`，SSR 返回 `masterUrl`，提取规则只认一种时另一路全空。
- **根因**：同一份数据来自服务端渲染和 XHR 两套序列化路径。
- **对策**：提取层归一化，同时认两种：
  ```python
  url = item.get("master_url") or item.get("masterUrl")
  ```
  这个模式在 `pick_best_stream()`、`_build_detail()`、`NoteLister` 里反复出现。

### 4. 编解码键名可能被混淆

- **现象**：`stream` 里没有 `h264`/`h265`，全是奇怪的键（实测见过 `EF4`）。
- **根因**：站点前端做了字段混淆。
- **对策**：`pick_best_stream()` 的兜底逻辑——遍历所有键、按分辨率降序挑，
  而不是只认固定编码名。

### 5. 详情页数据晚于 state 就绪 1–2 秒

- **现象**：第一次 `evaluate` 拿到了 state，但 `video.media.stream` 是空的。
- **根因**：视频流是异步水合的。
- **对策**：轮询 10 次、每次 600ms；但明确是图文时立即返回，不浪费时间。

### 6. 接口兜底抓到“相关推荐”里别人的视频

- **现象**：下载下来的是无关视频，note_id 对不上。
- **根因**：详情页接口同时返回当前笔记和相关推荐。
- **对策**：`ApiSniffer._payloads_with(note_id)` 先把响应序列化成字符串，
  只包含目标 note_id 的才参与解析。

## 二、风控与登录

### 7. 无 `xsec_token` 访问详情页 → 302 到 `/404/sec_?error_code=300031`

- **根因**：详情页必须有与主页会话关联的鲜活 token。
- **对策**：收集主页时把 `noteCard.xsecToken` 一起存下来，拼详情页 URL 时带上。
  手打用户 ID 分享链接没有这个参数，所以推荐用 App 分享链接。

### 8. 300012 是 IP 风控，和 Cookie 无关

- **现象**：换账号、换 Cookie 都没用，连续访问必中。
- **根因**：出口 IP 被标记（云服务器/机房 IP 或短时间高频自动化）。
- **对策**：停止访问 15–30 分钟冷却，或换网络、降频。**越重试越糟**。

### 9. 无头模式被重定向到登录页

- **根因**：无头是风控识别信号。
- **对策**：优先有头；或先有头登录一次再无头复用 profile；或 `--cookie` 注入。

### 10. `web_session` Cookie 不能作为登录判据

- **现象**：匿名访客也有这个 Cookie，误判为已登录。
- **根因**：站点对游客也下发该 Cookie。
- **对策**：以 `userInfo.userId` 是否存在为主要判据，`user.loggedIn` 只作为辅助。
  实测 `loggedIn` 已从 boolean 变成响应式对象。

### 11. profile 备份/恢复无效

- **现象**：`cp -r .xhs_profile 备份` 再拷回来，日志说有登录态但实际跳二维码。
- **根因**：Chrome Cookie 用 App-Bound Encryption，与 profile 原始路径/用户绑定。
- **对策**：**别备份 profile**。要保登录态就别删原目录；真要重置就直接删掉重新扫码。

### 12. 匿名下载不可行（结论性）

- **实测**：匿名可看主页、能拿到 10 篇列表和 token，但 `item.id` 为空、
  DOM 无 `<a href>`、点击卡片跳 `/explore/` 并弹登录框、`noteCard.video` undefined。
- **结论**：没 ID → 构造不出详情页 URL → 拿不到直链。别在这条路上投入时间。

## 三、GUI 层

### 13. 后台线程调 `evaluate_js` 导致任务完成但窗口卡死

- **现象**：日志显示任务跑完了，进度条不动、界面无响应。
- **根因**：pywebview 的 `evaluate_js` 必须从 UI 主线程调用。
- **对策**：前端 400ms 轮询 `get_updates(since)`，后台只写线程安全缓冲区。

### 14. pywebview 序列化对象每次都是新引用

- **现象**：`d.finish !== lastFinish` 永远为 true，完成提示每 400ms 弹一次，界面闪烁。
- **根因**：Python dict 每次跨语言都变成新的 JS 对象，JS 按引用比较。
- **对策**：传单调递增的**数字** `finish_run_id`，按值比较。新任务 `_reset()` 时清零。

### 15. toast 定时器累积

- **现象**：提示不消失、反复播动画。
- **根因**：每次 `toast()` 都新建 `setTimeout`，多个定时器互相开关。
- **对策**：复用单个句柄，调用前先 `clearTimeout(toastTimer)`。

### 16. GUI 看不到 INFO 日志

- **现象**：右侧面板只有零星警告，用户以为程序没在干活。
- **根因**：GUI 不走 `main()`，root logger 默认 WARNING。
- **对策**：`_run_async()` 里显式 `logging.basicConfig(level=logging.INFO)`。

### 17. public property 返回 `webview.Window` 导致窗口起不来

- **现象**：报 “Main window failed to start”。
- **根因**：pywebview 反射公开属性生成 JS API，返回 Window 会无限递归。
- **对策**：持有 Window 的属性名以下划线开头（如 `self._holder`）。

### 18. WebView2 内容截不到图

- **现象**：`PrintWindow` 截出来是空白。
- **根因**：WebView2 是独立渲染进程。
- **对策**：预览图用 Playwright 渲染同一份 HTML 生成，不用系统截图。

### 19. WebView2 下 `window.destroy()` 可能挂起

- **对策**：自测脚本收尾用 `os._exit(0)`。

### 20. GUI 端到端测试假失败

- **现象**：`TargetClosedError`，测试起不来。
- **根因**：上次残留的 chrome 进程占用 profile。
- **对策**：跑测试前先杀残留 chrome。

## 四、打包层

### 21. `build/` 里的同名 exe 报找不到 python311.dll

- **现象**：双击 exe 弹窗 `Failed to load Python DLL '...\build\build_exe\_internal\python311.dll'`。
- **根因**：PyInstaller 在 `build/` 和 `dist/` 各生成一个同名 exe，`build/` 那个没有同级 `_internal/`。
- **对策**：只运行 `dist/` 里的；`build.sh` 构建后自动清理 `build/`。
- **注意**：GUI 报错弹窗不写 stdout，只能靠报错里的路径定位。

### 22. 体积统计只算 exe 得到 7MB

- **根因**：漏算同级 `_internal/` 依赖目录（实际约 128MB）。
- **对策**：`du -sh` 统计整个产物目录。

### 23. 打包浏览器内核导致体积失控

- **对策**：只打包 driver（103MB），运行时探测本机 Chrome/Edge；内核让需要的用户自装。

### 24. macOS 产物架构搞混

- **根因**：把机器架构当成了产物架构。
- **对策**：自检时打印解释器架构；产物名带 `-arm64` / `-x64` / `-universal2`。
  universal2 要求所有二进制依赖都含双架构代码，配 universal2 版 Python 构建。

### 25. macOS `.app` 被 Gatekeeper 拦

- **对策**：临时 `xattr -cr <app>`；正式分发需 codesign + notarytool 公证。

## 五、沉淀下来的工程原则

1. **跨语言/跨进程只传基本类型**，复杂结构自己设计序列化协议。
2. **事件驱动用版本号，不用对象身份**。数字单调递是最省事的版本号。
3. **回调必须空值友好 + 异常隔离**，否则可选参数会变成新的故障源。
4. **状态文件是唯一真相来源**，原子写（`tmp.replace`），损坏时降级而不是崩。
5. **抓取逻辑不依赖接口路径**，靠“数据长什么样”识别，而不是“接口叫什么名字”。
6. **站点改版的适配依据靠日志**：`--dump-api -v` 打印出接口路径，改版时一眼看到变化。
7. **平台差异集中到一处**，核心代码零 `sys.platform` 判断。
8. **不把法律与合规当注释**：README 首屏就写清使用边界，图标也不用官方 logo。

## 六、如果要继续扩展

几个自然的方向，都建立在现有架构上：

- **图片笔记下载**：`fetch_note_detail()` 已经能识别图文，只需补图片列表提取 + 下载分支
- **增量同步**：用 `state.json` 的 `index` 里的时间戳做“只下新发布”
- **代理/网络配置**：`httpx.AsyncClient` 和 Playwright 都支持 proxy，可在 `JobConfig` 加字段
- **任务队列**：`run_job` 已经是纯函数式入口，外面套队列调度不需要改核心
- **更细的进度事件**：在解析阶段也发 `file_count` 类事件，进度条会更平滑

## 结语

整套实现看起来有很多“ workaround ”，但它们不是随手糊的补丁——
每一条都对应一个真实约束：**站点不给 API、风控很敏感、跨语言边界有坑、三个平台各有一套 WebView**。

理解了约束，代码就不再是“奇怪的技巧”，而是“在这种条件下最合理的做法”。
