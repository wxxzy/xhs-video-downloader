# 02 · 核心原理：页面数据与风控

> 目标：回答两个问题——**数据到底藏在哪**，以及**为什么代码要写得这么绕**。
> 这一篇是整套实现的理解枢纽。看穿了它，后面所有“看似奇怪”的代码都会变得合理。

---

## 1. 数据有三条入口，没有一条是稳定的

小红书没有公开 API。工具拿到笔记数据靠的是三条互补路径：

| 路径 | 实现 | 优点 | 弱点 |
| --- | --- | --- | --- |
| ① SSR 内嵌数据 | `window.__INITIAL_STATE__` | 首屏就有，自带新鲜的 `xsec_token` | 站点改版就变结构 |
| ② 接口响应拦截 | `ApiSniffer` / `NoteLister._handle_response` | 不依赖接口路径，改版也能活 | 依赖页面真的发起请求 |
| ③ DOM 兜底 | 解析 `a[href*='/explore/']` | 最后一道保险 | 只能拿 ID，拿不到视频直链 |

对应关系在源码里：

- `NoteLister._ssr_scrape()`（`xhs_video_downloader.py:600`）
- `NoteLister._handle_response()`（`:550`）
- `NoteLister._dom_scrape()`（`:716`）
- `fetch_note_detail()`（`:820`）—— 详情页同样走 SSR + 接口两条路

### 一个实测事实：新版主页首屏不走列表接口

早期版本打开主页会发出 `user_posted` 之类的接口，拦截就行。
新版改为把首屏笔记**直接内嵌在 HTML 里**（SSR）：

```js
window.__INITIAL_STATE__.user.notes
  → notes[tabIndex][]          // 分组数组
  → item.id                    // 笔记 ID
  → item.noteCard.xsecToken    // 关键！访问详情页的通行证
  → item.noteCard.displayTitle
  → item.noteCard.video.media.stream
```

字段名是 **camelCase**（`xsecToken` / `noteId` / `displayTitle`），而接口返回的是 **snake_case**
（`xsec_token` / `note_id` / `display_title`）。所以提取层专门做了归一化，
`pick_best_stream()`（`xhs_video_downloader.py:103`）同时认两种写法：

```python
url = item.get("master_url") or item.get("masterUrl")
backups = item.get("backup_urls") or item.get("backupUrls") or []
```

> **经验**：凡是“网站自己注入的数据”，都要同时准备 snake_case 和 camelCase 两套键。

## 2. 最大的坑：`__INITIAL_STATE__` 是 Vue 响应式对象

这是整套代码里最反直觉的一点。

你可能会想，直接在页面里执行：

```js
return JSON.stringify(window.__INITIAL_STATE__)
```

然后 Python 侧 `json.loads` 就完事了。**实际会得到 `None`，而且不报错。**

原因：Vue 的响应式对象内部有循环引用（父指向子、子又指回父），
Playwright 跨进程序列化时会静默失败。

### 解法：页面内逐字段拆成基本类型，用自定义分隔符拼串

看 `_ssr_scrape()` 里的 JS（`:609-659`）：

```js
out.push([
  String(it.id),
  String(card.type || it.type || ''),
  String(card.displayTitle || card.display_title || ''),
  String(card.xsecToken || it.xsecToken || card.xsec_token || ''),
  String(card.time || it.time || ''),
  String(video ? (video.duration || 0) : ''),
  streamSummary,
].join('`'));           // 字段用反引号分隔
return out.join('\u0001');  // 行用 \x01 分隔
```

Python 侧再拆回来：

```python
for line in raw.split("\x01"):
    parts = line.split("`")
    note_id, ntype, title, token, ts = parts[0], parts[1], parts[2], parts[3], parts[4]
```

详情页的 `_SSR_DETAIL_JS`（`:860`）用了同样的思路，只是多套了一层：
流信息用 `~` 分隔字段、`^` 分隔多条流。

还有一个细节：代码里到处是

```js
let dm = s.note.noteDetailMap;
if (dm && dm._value) dm = dm._value;
```

Vue 3 的 `ref` 会把真实值藏在 `._value` 里，取一次才能拿到数组/对象。

> **可复用原则**：跨进程序列化只传字符串、数字、布尔值。复杂结构你自己设计分隔符协议，
> 别指望框架帮你搞定循环引用。

## 3. `xsec_token`：整个工具的核心钥匙

### 它解决什么问题

详情页 URL 长这样：

```
https://www.xiaohongshu.com/explore/<笔记ID>?xsec_token=<46位串>&xsec_source=pc_user
```

没有 `xsec_token` 访问详情页，会被 302 到：

```
/404/sec_?error_code=300031
```

页面提示“当前笔记暂时无法浏览”。这就是 **300031 风控**。

关键点：**token 是新鲜的、与主页绑定的**，不能自己编，也不能用很久以前的。
所以 `NoteLister` 在收集主页笔记时，把每条的 `xsecToken` 一起存进 `notes` 字典，
后面拼 URL 时带上：

```python
url = f"{XHS_HOME}/explore/{note_id}"
if token:
    url += f"?xsec_token={token}&xsec_source=pc_user"
```

`resolve_profile()`（`:1151`）同样会把用户输入链接里的 `xsec_token` / `xsec_source`
原样保留到主页 URL——所以从 App 分享出来的链接比手打用户 ID 更“香”。

### 另一个错误码：300012

```
IP存在风险，请切换可靠网络环境后重试
```

这是 **IP 级风控**，和 Cookie 无关。实测连续多次自动化访问必中，
连登录态也会被拦。对策只有：等 15–30 分钟冷却、换网络、或降低访问频率
（`--delay` / `--scroll-pause`）。

### 三层防风控策略

```
① 新鲜 token        —— 从主页 SSR 现场取，不缓存复用
② 频率控制          —— --delay 1.5s / --scroll-pause 1.2s
③ 瞬时失败重试      —— 检出 300031 → 解析 redirectPath → 2 秒后重试一次
```

第 ③ 条在 `fetch_note_detail()`（`:839-854`）：

```python
if "error_code=300031" in final_url or "/404/sec_" in final_url:
    m = re.search(r"redirectPath=([^&]+)", final_url)
    if m:
        original = unquote(m.group(1))
        await page.wait_for_timeout(2000)
        final_url = await _goto(original)
```

## 4. 为什么一定要登录：匿名态实测结论

有人会问：能不能不登录，直接匿名抓列表和视频？

**结论：不可行。** 用全新空白 profile（非无头）实测：

| 能力 | 匿名态 |
| --- | --- |
| 访问用户主页 | ✅ 可以，SSR 能拿到 10 篇列表和 token |
| `item.id` / `noteCard.noteId` | ❌ 均为空字符串，ID 被剥离 |
| DOM 里的 `section.note-item` | ✅ 渲染了 10 张卡片 |
| 卡片上的 `<a href>` | ❌ 一个都没有 |
| 点击卡片 | ❌ 跳 `/explore/`（无 ID）并弹登录框 |
| `noteCard.video` | ❌ undefined，列表页不给直链 |

逻辑链很干脆：**没 ID → 构造不出详情页 URL → 拿不到视频直链**。
主页在匿名态下只是 SEO 展示壳，内容入口被锁死了。别在这条路上浪费时间。

## 5. 详情页数据晚到：为什么轮询 10 次

`__INITIAL_STATE__` 先就绪，但 `stream` 里的视频直链往往晚 1–2 秒才水合完成。
所以 `fetch_note_detail()` 不是读一次就完，而是（`:908-916`）：

```python
for _ in range(10):
    detail_raw = await page.evaluate(_SSR_DETAIL_JS)
    if detail_raw and detail_raw.startswith("OK"):
        break
    await page.wait_for_timeout(600)
```

但如果拿到的 `type` 明确是图文（`normal`），就立刻返回、不再等视频流：

```python
if ntype and ntype not in ("video",) and stream is None:
    return {"type": ntype, ...}   # 图文笔记：确认后不再重试
```

而如果是 `video` 类型但流还没来，循环继续；10 次都拿不到，再走接口嗅探兜底：

```python
found = sniffer.find_video_for_note(note_id)
```

`ApiSniffer` 的关键设计是**先过滤包含目标 note_id 的响应**（`:228`），
否则很容易把“相关推荐”里别人的视频当成当前笔记的：

```python
for _url, payload in reversed(self.captured):
    blob = json.dumps(payload, ensure_ascii=False)
    if note_id and note_id in blob:
        result.append(payload)
```

## 动手实验

1. 打开浏览器 DevTools → Network，访问一个用户主页，搜索含 `note` 的 XHR，
   观察新版主页是否真的没有列表接口。
2. 在 Console 里执行 `Object.keys(window.__INITIAL_STATE__.user)`，
   再试着 `JSON.stringify(window.__INITIAL_STATE__)`——看看是不是报错或异常。
3. 用 `--dump-api -v` 跑一次，看工具巡检到的接口路径。这正是站点改版后适配的依据。
4. 拿一个详情页 URL，**去掉 `xsec_token` 参数**再访问，亲眼看看 300031 长什么样。
