# 01 · 环境搭建与第一次运行

> 目标：先让程序跑起来，亲眼看到 `state.json` 和一个真实的 `.mp4` 落地。
> 不追求理解每一行，先把“输入是什么、输出是什么”建立起来。

---

## 1. 安装依赖

项目根目录执行：

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
python -m playwright install chromium
```

`requirements.txt` 里只有四样东西，各司其职：

| 依赖 | 作用 |
| --- | --- |
| `playwright` | 驱动真实浏览器，登录、滚动、读页面内嵌数据 |
| `httpx` | 拿到直链后并发下载视频文件 |
| `pywebview` | 桌面窗口外壳（GUI 模式才需要） |
| `Pillow` | 生成应用图标（打包时需要） |

> **浏览器内核可以省掉**：GUI 会优先用本机已安装的 Chrome / Edge。
> 只有都没装时才需要 `playwright install chromium` 下载约 200MB 内核。
> 命令行模式如果指定了 `--channel chrome`，也可以复用本机浏览器。

## 2. 第一次运行：只用 `--max 2`

**不要一上来就全量跑。** 先用 `--max` 限制只处理 2 篇，验证登录和解析都正常：

```bash
python xhs_video_downloader.py \
  --user https://www.xiaohongshu.com/user/profile/<24位用户ID> \
  --list-only
```

`--list-only` 只列清单不下载。输出类似：

```
共 8 个视频笔记：
    1. 67a461...  标题一
    2. 67b572...  标题二
```

确认清单对得上，再去掉 `--list-only`：

```bash
python xhs_video_downloader.py \
  --user https://www.xiaohongshu.com/user/profile/<24位用户ID> \
  --max 2
```

首次运行会弹出一个浏览器窗口，上面是登录二维码，用小红书 App 扫一下。
登录态写入 `./.xhs_profile/`，**以后运行自动复用，不用再扫**。

## 3. 看懂输出目录

```
downloads/<用户ID>/
├── 20241018_<笔记ID>_<标题>.mp4   ← 视频原片
├── state.json                      ← 断点续传状态
└── notes_index.json                ← 元数据索引（部分版本）
```

`state.json` 的结构值得打开看一眼，它就是整个“断点续传”机制的载体：

```json
{
  "downloaded": { "笔记ID": "文件名.mp4" },
  "failed":     { "笔记ID": "失败原因" },
  "skipped":    { "笔记ID": "非视频笔记" },
  "index":      [{ "note_id": "...", "size_bytes": 81321553, ... }]
}
```

三个桶的语义不同，这是后面理解“重跑时哪些会重试”的关键：

- `downloaded` → 永久跳过，不再碰
- `skipped` → 确认是图文，永久跳过
- `failed` → **下次重跑会重试**

写代码时对应 `select_pending()`（`xhs_video_downloader.py:280`）：

```python
return [
    n for n in notes
    if n.get("type") in ("video", "unknown")
    and n["id"] not in (downloaded or {})
    and skipped.get(n["id"]) != "非视频笔记"
]
```

注意 `failed` 不在这个过滤条件里——这是有意设计。

## 4. GUI 模式启动

```bash
python gui/app.py
```

界面左侧填链接、保存目录和高级参数，右侧是实时日志与进度条。三个入口按钮：

- **开始下载** —— 账号批量模式
- **仅列出清单** —— 对应 CLI 的 `--list-only`
- **仅登录** —— 只完成扫码，不下载（第一次用可以先跑这个）

扫码登录时二维码直接显示在窗口内的弹层里，不用切到浏览器窗口找。

---

## 5. 三个参数先混个脸熟

| 参数 | 默认 | 什么时候调 |
| --- | --- | --- |
| `--delay` | 1.5 | 详情页被拦（300031）时调大到 3 |
| `--concurrency` | 2 | 网络好可以调到 4，别太激进 |
| `--scroll-pause` | 1.2 | 主页只加载部分笔记时调大到 2.5 |

现在不用调，记住有这几个旋钮就行。第 2 篇会解释它们和风控的关系。

## 动手实验

1. 跑一次 `--list-only`，把输出清单和网页上看到的笔记数量对比。
2. 打开生成的 `state.json`，确认三个桶的长相。
3. 删除一个已下载视频文件但保留 `state.json`，再跑一次同命令——程序会因为 `downloaded` 桶里有记录而**跳过**它，不会重新下载。
4. （可选）把某个笔记 ID 从 `downloaded` 挪到 `failed`，重跑观察它被重新处理。

第 3 步的结果可能有点反直觉：文件没了但状态还在。这正是“状态文件是唯一真相来源”的设计取舍——想强制重下，就把对应记录删掉。

## 常见起步问题

**没弹出二维码？** 确认没有 `--headless`。无头模式下页面会被风控重定向到登录页。

**提示“已检测到保存的登录状态”但实际没登录？** 这是 profile 被复制过的典型症状。Chrome Cookie 用 App-Bound Encryption 与原始路径绑定，**备份/恢复 profile 目录是无效的**。删掉 `.xhs_profile` 重新扫码。

**收集到 0 篇？** 依次排查：账号是否私密、是否弹了滑块验证码、登录是否失效。

## 小结

- 输入：主页链接 / 用户 ID / App 分享短链，三种都能解析
- 输出：`downloads/<用户ID>/` 下的 mp4 + `state.json`
- 登录态：`.xhs_profile/`，删了就等于退出登录
- 重跑策略：已下载和已确认图文的跳过，失败的自动重试
